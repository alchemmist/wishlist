# Аудит Wishlist

## Область и результат

Проверены исходники бэкенда, интерфейса, хранилища, схема и миграция SQLite, OIDC, зависимости, Dockerfile и workflow. Приложение запущено локально, главные пользовательские сценарии проверены браузерными E2E-тестами.

Все описанные ниже исправления находятся в рабочем дереве. Продакшен, Authentik и RustFS не изменялись; деплой не выполнялся.

### Последний результат проверок

- **71 pytest-проверка**: 63 проверки приложения (API, права, конкурентные запросы, валидация, миграции, локальные изображения и S3-контракт) и 8 регрессионных проверок quality/deploy-пайплайна.
- **148 E2E-проверок**: 37 сценариев × Chromium desktop, Firefox desktop, Chromium/Pixel 7 и WebKit/iPhone 13. Мобильные устройства эмулируются, это не физические телефоны.
- Дополнительный повторный прогон: **168/168 passed**, без автоматических retries (до последнего конфигурационного теста S3; сценарии приложения те же).
- Прогоны выполнены также на **Python 3.13**, используемом Dockerfile/CI, в отдельном окружении.
- `pip-audit -r requirements.txt`: известных уязвимостей не найдено после обновления зависимостей.
- `npm audit --audit-level=low`: 0 уязвимостей.
- `node --input-type=module --check < static/app.js` и `git diff --check`: без ошибок.
- Существующая локальная SQLite-база мигрирована **на временной копии через SQLite backup API**: `integrity_check = ok`, нарушений внешних ключей нет. Оригинал этой проверкой не изменялся.
- Вручную просмотрены браузерные скриншоты десктопного интерфейса владельца и мобильного публичного списка с открытой формой бронирования. В E2E отдельно проверена ширина 320 px без горизонтального скролла.

## Исправленные проблемы

### Высокий приоритет: безопасность и целостность данных

| Проблема | Исправление и проверка |
| --- | --- |
| Самописный OIDC callback не проверял подпись и claims ID token | Используется Authlib с проверкой JWT, issuer, audience, expiry, nonce, одноразового state и PKCE S256. `sub` userinfo обязан совпадать с проверенным ID token. Положительный поток и отрицательные случаи проходят через локальный OIDC-провайдер по настоящему HTTP. |
| Владение проверялось по имени; база допускала разных владельцев с отличающимися регистром именами | Права проверяются по числовому ID владельца. Создан уникальный Unicode-индекс имён пользователей. Коллизия не объединяет аккаунты и не передаёт права: вход возвращает 409. |
| Общий SQLite connection между запросами смешивал транзакции | На каждый запрос отдельное соединение с rollback/close. Для решений read-then-write используются транзакции, включён WAL. |
| Гонки бронирования и снятия | `BEGIN IMMEDIATE` охватывает проверку существования подарка и решение о брони. Из 24 одновременных разных имён проходит ровно одно; одинаковое имя идемпотентно. Неуспешные попытки не оставляют лишних гостей. |
| SQLite-операции в async callback могли заблокировать event loop и вызвать `database is locked` при входе одновременно с бронью | Запись профиля вынесена в threadpool; обработчик загрузки фото синхронный. Ошибка воспроизвелась в E2E и исчезла после исправления, повторные прогоны проходят. |
| Потерянный ответ успешного POST создавал дубль при повторе | Форма сохраняет UUID операции до завершения. Уникальный `(owner_id, creation_key)` позволяет безопасно повторить создание. Проверяется потеря ответа **после сохранения на сервере**, а не только ошибка до отправки. |
| У сессии был публично известный fallback secret | Для HTTPS ключ обязателен. В локальном HTTP без ключа генерируется случайный ключ процесса. Cookie остаётся HttpOnly/SameSite=Lax и Secure для HTTPS. |
| Не было явной защиты мутирующих запросов от cross-site вызовов | Проверяются Origin и Sec-Fetch-Site; добавлены CSP, frame-ancestors, nosniff и no-store для динамических ответов. |
| Проверка размера файла срабатывала после получения неограниченного multipart | Есть ASGI-лимит тела запроса при чтении, включая chunked: 9 MB multipart и 256 KiB прочие тела. Сам файл дополнительно ограничен 8 MB. |
| Любые данные можно было загрузить как картинку | Pillow проверяет реальный формат, структуру, декодирование и лимит 25 мегапикселей. SVG/HTML, подделка MIME, обрезанные и oversized изображения отклоняются. |
| Чтение media могло выходить за каталог хранилища | Проверяются относительный ключ и resolved path, в том числе абсолютные пути, `..` и symlink-выход за корень. Новые ключи используют ID владельца, а не username. |
| Замена SQLite NOCASE на Unicode без перестройки старого индекса давала некорректные результаты | Используется отдельная UNICODE_NOCASE collation. Миграция объединяет гостей-дубликатов с переносом броней и создаёт Unicode-индексы. Коллизии владельцев блокируют старт с понятной ошибкой, а не объединяют аккаунты. |
| Были уязвимые версии Authlib, Starlette и multipart; выбранная первоначально версия Pillow тоже требовала обновления | Обновлены runtime-зависимости с повторной проверкой API и E2E; текущий dependency audit чистый. |

### Основные функции и интерфейс

- Исправлен конфликт `form.title` с DOM-свойством: раньше добавление/редактирование могло не работать.
- Цена теперь видна в карточках, описание и ссылки поддерживают несколько строк.
- Сервер проверяет длины полей, количество/длину ссылок, схему, host, credentials, port и запрещённые символы URL **до изменения карточки**. Клиент тоже отбрасывает не-HTTP(S) ссылки, включая старые небезопасные данные.
- Ошибка фото не теряет форму и не создаёт новый подарок при повторе. Ошибка сети также сохраняет введённые данные.
- Заблокирована повторная отправка и смена редактируемой карточки во время сохранения.
- Есть отмена редактирования, удаление подарка с подтверждением, удаление фото и очистка старого фото при замене. Отмена после частичного сохранения перечитывает список.
- Ссылки-магазины имеют доступные имена; остальные хосты корректно переносятся.
- Публичный список не зависит от доступности отдельного `/api/me`.
- Исправлены stale empty-state, ошибки загрузки списка, кнопка повторной загрузки и защита от устаревших ответов клиента.
- Поповер брони ограничен видимой областью, учитывает visualViewport, закрывается Escape с возвратом фокуса. Ошибки имени и конфликта показываются пользователю.
- Фото увеличивается мышью и клавиатурой. Исправлено игнорирование Escape во время открытия и работа с reduced motion; фокус возвращается к изображению.
- Переписаны накопившиеся конфликтующие CSS-правила. Проверены карточки без фото, длинные названия/описания, узкие экраны, preview и меню аккаунта.
- Исправлен выход: он больше не перенаправляет сразу обратно в OIDC-вход. В меню есть ссылка на свой список; ошибки выхода не скрываются.
- Ошибки входа показываются отдельной читаемой страницей со ссылкой повторить вход, а не сырым JSON/500.
- Уменьшено количество SQL-запросов чтения списка: ссылки выбираются одним запросом вместо отдельного запроса на каждый подарок; добавлены индексы.

### Хранилище и эксплуатация

- S3 больше не пытается создавать бакет при запуске и не скрывает ошибки provisioning. Бакет должен существовать заранее.
- Частичная S3-конфигурация останавливает запуск вместо неожиданного перехода на локальный диск.
- Настроены timeout/retry S3. Настоящий NoSuchKey даёт 404, ошибка доступа/недоступности — 503, а не ложный 404. Поток ответа S3 закрывается.
- Ошибка очистки старого объекта логируется и не превращает успешное сохранение в повторное создание.
- Добавлены `.dockerignore`, тестовые зависимости, npm lockfile, Playwright-конфигурация и воспроизводимый E2E-сервер. Тестовые auth-маршруты не добавлялись в приложение: провайдер существует только в `tests/e2e_server.py` и не попадает в Docker image.
- Проверки оформлены в `qg.yaml` через quality-graph 0.2.0: 11 узлов, генерируемые PR/push/publisher workflow, JUnit-адаптеры, аудит зависимостей и артефакты E2E. Деплой запускается отдельно только после успешного доверенного графа на main и использует проверенный SHA. Проверены `qg validate`, actionlint и переносимые команды узлов; сам GitHub workflow и административные required checks локально не запускались. См. [CI.md](CI.md).

## Матрица E2E

Каждый сценарий выполняется в четырёх браузерных профилях:

1. OIDC-вход, пустой список, сохранение сессии после reload, ссылка на свой список, выход.
2. Создание подарка с фото, ценой, описанием и всеми типами ссылок; zoom; редактирование; отмена; удаление фото; отмена/подтверждение удаления подарка.
3. Публичный список без редактора; бронь кириллическим именем; сохранение после reload; отказ при неверном имени; снятие другим регистром того же имени.
4. Чужой вошедший пользователь: нет редактора, API запрещает добавление, редактирование, удаление и загрузку фото.
5. Неудачная загрузка фото и успешный повтор без дубля.
6. Сетевой сбой сохранения, сохранность формы и защита от двойного submit.
7. Небезопасная ссылка, oversized фото и поддельная картинка; восстановление после ошибки.
8. Сбой account API, сбой списка/повтор и неизвестный список.
9. Ширина 320 px, длинное название, доступность ссылок и границы поповера.
10. XSS-строка отображается текстом; небезопасные API-ссылки отклоняются.
11–16. Отказ OIDC при неверной подписи, nonce, audience, issuer, истёкшем токене и несовпадении subject.
17. Потеря ответа создания после успешной записи и безопасный повтор того же UUID.
18. Сетевая ошибка брони и конфликт со свежей бронью другого гостя.
19. Клавиатурное увеличение фото с reduced motion и немедленным Escape.
20. Неверный state, повтор callback и понятная страница восстановления.
21. Попытка входа с регистровой коллизией username не захватывает прежний аккаунт.
22. Авторизованный пользователь бронирует/снимает бронь одним нажатием без формы имени, с username из сессии; другой вошедший пользователь не может снять эту бронь даже с подставленным именем.
23. Переключатель дожидается ответа об аккаунте и корректно повторяет запрос после сетевой ошибки, не открывая форму имени.

## Ограничения и оставшиеся риски

1. **Настоящие Authentik и RustFS не проверены**: в окружении не было их конфигурации/учётных данных. OIDC E2E использует отдельный локальный провайдер с RSA JWT и проверкой PKCE; S3 проверен Stubber-тестами контракта SDK. Нужен smoke-test реальных интеграций после выкладки.
2. **Docker image не собран локально**: Docker daemon недоступен. Python 3.13 и зависимости проверены отдельно, но это не замена сборке контейнера и проверке volume permissions в кластере.
3. **Перед выкладкой нужен backup SQLite** через SQLite backup API или остановленное приложение. Из-за WAL нельзя копировать только живой `.sqlite` файл. Объединение гостей при миграции нельзя автоматически обратить без backup. При конфликте имён владельцев потребуется ручное разрешение; никакой аккаунт не объединяется автоматически.
4. **Бронь по имени — не аутентификация.** Зная имя гостя, можно снять его бронь: это текущий контракт продукта. Для реальной защиты нужен секретный токен/код гостя или вход. Не добавлялся несовместимый способ бронирования без решения владельца продукта.
5. **Нет распределённого rate limiting, квот на количество подарков и фонового сборщика orphan-файлов.** Защита от публичного спама/brute force должна дополняться ingress-лимитами; неудачная очистка S3 логируется, но не попадает в durable retry queue.
6. **Один pod и SQLite на локальном volume остаются ограничением доступности.** Dockerfile также по-прежнему запускает процесс от root; перевод на непривилегированный UID нужно согласовать с fsGroup/правами тома в отдельном homelab-чарте.
7. В тестовых логах остаются предупреждения сторонних библиотек о будущем переходе с httpx на httpx2. Тесты проходят; переход транспорта не смешивался с исправлением функций приложения.

повторный Save восстанавливает фактически загруженные IDs. Уже сохранённые
данные при Stop не откатываются. Проверены 27 фото в редактировании, файл
больше 9 МБ, медленная загрузка/таймер, остановка/повтор, 30 МП, streaming,

Просмотрена конфигурация homelab: у Wishlist ingress нет body-size middleware,
у traefik-edge read timeout уже 0s. Инфраструктура не изменялась; реальные
Authentik/RustFS credentials в локальных тестах не используются.


## Clipboard photos

Photo picker разделён на Files / Paste. Clipboard API вызывается только явным
нажатием Paste; при запрете/отсутствии API даётся fallback Ctrl+V/⌘V в зоне
добавления. Событие paste с изображением добавляет файлы в ту же очередь без
запроса разрешения Clipboard API. Пустой/текстовый буфер не создаёт фото.
Пока идёт чтение, Save объясняет ожидание; результат после Cancel/смены
редактируемой карточки игнорируется. E2E во всех профилях используют изолированный
clipboard API fixture и paste-event payload (не персональный системный буфер),
проверяют сохранение, отказ/пустой буфер, fallback и поздний результат.


## Metadata-only saves, floating activity and observability

Тайтл-only Save больше не запускает два PATCH галереи и загрузку списка/аккаунта:
один PATCH метаданных, карточка обновляется локально из ответа. Порядок сохраняется
только при изменении; новые upload по-прежнему согласуются по UUID после ошибок.
