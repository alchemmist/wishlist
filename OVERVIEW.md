# Wishlist

Публичные списки желаний на https://wishlist.alchemmist.xyz. У человека один список, его можно открыть без входа и забронировать подарок своим именем. На `/` вошедший перенаправляется на свой список; гость видит подсказку и ссылку входа.

## Что видит человек

- `/{username}` — список. Имя берётся из Authentik (`preferred_username`) и у одного человека ровно один список.
- `/login` — вход через Authentik. После входа в углу круглый аватар; нажатие открывает выход.
- Владелец добавляет подарок: название, описание, цена, ссылки и до 20 фото. Фотографии можно выбрать сразу несколькими файлами или добавлять порциями; порядок меняется перетаскиванием самой фотокарточки (включая touch), курсор — grab/grabbing. Ручек, стрелок и общей кнопки удаления фото нет. Первое фото — обложка. Круглая кнопка с корзинкой появляется справа сверху при наведении/фокусе на фотокарточку; на touch — после касания. Изменения применяются кнопкой Save; Cancel отменяет несохранённое редактирование. Чужой список редактировать нельзя. У своего подарка рядом с названием маленький карандаш. В редакторе можно отменить изменения, удалить фото или удалить подарок с подтверждением.
- Авторизованный пользователь включает и выключает переключатель без формы имени: сервер использует его username из сессии Authentik и игнорирует имя из запроса. Чужую бронь таким переключателем снять нельзя.
- Гость бронирует подарок именем. Имя уникально без учёта регистра: `Masha` и `masha` — один человек. Снять бронь можно только тем же именем. Поле имени открывается у переключателя, который его вызвал.
- Ссылки на Ozon, Wildberries и Яндекс Маркет показываются значками. Остальные — текстом хоста. Принимаются только `http` и `https`.
- Клик по фото открывает его через medium-zoom, как на блоге.

Кто может войти, решает приложение Authentik, а не проверка группы в этом репозитории. Внешним людям нужна группа `app-wishlist-user`. Приложение есть на панели Authentik.

## Как сложено

Один процесс FastAPI отдаёт и страницу, и API.

| Путь | Зачем |
| --- | --- |
| `app/main.py` | маршруты, сессия, вход через OIDC |
| `app/db.py` | SQLite: пользователи, подарки, ссылки, гости, брони |
| `app/storage.py` | запись фото в S3 или на диск |
| `static/` | страница, стили и клиентский скрипт |
| `tests/test_reserve.py` | уникальность имени и снятие брони |

Вход использует Authlib: проверяются state, nonce, PKCE S256, подпись и claims ID token, а также совпадение subject в userinfo. Сессия — подписанная HttpOnly cookie; после входа в ней хранится только `sub` из Authentik. Во время входа cookie временно содержит OIDC state. Для HTTPS нужен заданный `SESSION_SECRET`. После входа пользователь создаётся или обновляется в `users`. Права проверяются по ID владельца, имена аккаунтов уникальны с Unicode-нормализацией без учёта регистра.

Фотографии сохраняются после карточки: каждая отправляется через идемпотентный `PUT /api/items/{id}/images/{uuid}`, порядок и удаления — `PATCH /api/items/{id}/images`. При потере ответа повторное сохранение восстанавливает состояние по серверным идентификаторам и не создаёт дублей. Таблица `item_images` хранит порядок; старое `image_key` остаётся совместимым полем обложки. Миграция сохраняет существующие одиночные фото без копирования объектов. Старые `/image` endpoints оставлены для совместимости: POST заменяет всю галерею одним фото, DELETE удаляет все фото. Если заданы `S3_ENDPOINT`, `S3_ACCESS_KEY` и `S3_SECRET_KEY`, файл идёт в бакет `wishlist` на RustFS. Иначе он лежит в `/data/media`. В карточке хранится ключ объекта, а браузер берёт картинку через `/media/{key}`: приложение само читает её из бакета. JPEG, PNG, WebP и GIF отдаются со своим типом. Лимит файла — 8 МБ. Изображение проверяется Pillow, включая формат, структуру, декодирование и лимит 25 мегапикселей. Общий multipart ограничен 9 МБ ещё при чтении, остальные тела запросов — 256 КиБ. Если загрузка не удалась, форма остаётся открытой и пишет, что фото не сохранилось. Повтор не создаёт дубль: форма хранит ID сохранённой карточки, а UUID операции защищает и от потери ответа первоначального создания. При замене/удалении фото старый объект удаляется; неудачная очистка логируется.

SQLite работает в WAL-режиме; у каждого запроса своё соединение и rollback при ошибке. Бронирование сериализуется write-транзакцией. При запуске миграция создаёт индексы и объединяет регистровые Unicode-дубли гостей с переносом броней. Конфликт имён владельцев останавливает старт без объединения аккаунтов; перед выкладкой нужен backup через SQLite backup API.

SQLite — файл `/data/wishlist.sqlite` на томе, который может быть примонтирован только к одному узлу. Поэтому в кластере один под, и он закреплён за `socrat-0`.

## Деплой

Все проверки описаны в `qg.yaml` (официальное имя декларации quality-graph 0.2.0). Команды `qg generate` и `qg validate` генерируют и проверяют workflow для PR, push в `main` и доверенной публикации PR-дашборда. Граф включает валидацию CI, actionlint, синтаксис Python/JavaScript, pytest с JUnit, аудит Python/npm и четыре отдельных E2E job. Артефакты Playwright сохраняются и при падении тестов; структурированные результаты обрабатываются quality-graph.

После успешного графа на `main` отдельный `.github/workflows/deploy.yaml` получает `workflow_run`, собирает проверенный `head_sha`, публикует образ в Harbor `harbor.socrat.alchemmist.xyz/homelab/wishlist` и вызывает `alchemmist/deploy-to-socrat@v1`. PR/fork/feature-branch результаты не допускаются до секретов деплоя. Перед выкладкой проверяется актуальность SHA относительно `main`. Для ручного релиза запускается **Quality Graph** на `main`, без обхода проверок. Шаг деплоя записывает digest образа в репозиторий homelab; Argo CD подхватывает чарт и обновляет под. Подробнее, включая bootstrap и required checks: [CI.md](CI.md).

Сам чарт, ingress, DNS и секреты живут в homelab, не здесь. Секрет пода даёт клиента Authentik, ключ сессии и ключ бакета. К порту RustFS 9000 под пускает сетевая политика `rustfs-isolation`, правило `wishlistMedia`. Учётная запись бакета отдельная: пользователь видит только бакет `wishlist`.

Публичное имя — `wishlist.alchemmist.xyz`, TLS выпускает cert-manager. DNS зоны ведётся на своих Knot, не записью у регистратора.
