# Wishlist

Публичные списки желаний на https://wishlist.alchemmist.xyz. У человека один список, его можно открыть без входа и забронировать подарок своим именем. Отдельной главной страницы нет: `/` отправляет вошедшего на свой список, остальных — на страницу входа.

## Что видит человек

- `/{username}` — список. Имя берётся из Authentik (`preferred_username`) и у одного человека ровно один список.
- `/login` — вход через Authentik. После входа в углу круглый аватар; нажатие открывает выход.
- Владелец добавляет подарок: название, описание, цена, ссылки и одно фото. Чужой список редактировать нельзя. У своего подарка рядом с названием маленький карандаш.
- Гость бронирует подарок именем. Имя уникально без учёта регистра: `Masha` и `masha` — один человек. Снять бронь можно только тем же именем. Поле имени открывается у переключателя, который его вызвал.
- Ссылки на Ozon, Wildberries и Яндекс Маркет показываются значками. Остальные — текстом хоста. Принимаются только `http` и `https`.
- Клик по фото открывает его через medium-zoom, как на блоге.

Кто может войти, решает приложение Authentik, а не проверка группы в этом репозитории. Внешним людям нужна группа `app-wishlist-user`. Приложение есть на панели Authentik.

## Как сложено

Один процесс FastAPI отдаёт и страницу, и API.

| Путь | Зачем |
| --- | --- |
| `app/main.py` | маршруты, сессия, вход через OIDC |
| `app/db.py` | SQLite: пользователи, подарки, ссылки, гости, брони |
| `app/storage.py` | запись фото в S3 или на диск |
| `static/` | страница, стили и клиентский скрипт |
| `tests/test_reserve.py` | уникальность имени и снятие брони |

Сессия — подписанная cookie. В ней хранится только `sub` из Authentik. После входа пользователь создаётся или обновляется в `users`.

Фото сохраняется отдельным запросом `POST /api/items/{id}/image` после сохранения карточки. Если заданы `S3_ENDPOINT`, `S3_ACCESS_KEY` и `S3_SECRET_KEY`, файл идёт в бакет `wishlist` на RustFS. Иначе он лежит в `/data/media`. В карточке хранится ключ объекта, а браузер берёт картинку через `/media/{key}`: приложение само читает её из бакета. JPEG, PNG, WebP и GIF отдаются со своим типом. Лимит файла — 8 МБ. Если загрузка не удалась, форма остаётся открытой и пишет, что фото не сохранилось.

SQLite — файл `/data/wishlist.sqlite` на томе, который может быть примонтирован только к одному узлу. Поэтому в кластере один под, и он закреплён за `socrat-0`.

## Деплой

Пуш в `main` запускает `.github/workflows/deploy.yaml`: сначала pytest, затем образ в Harbor `harbor.socrat.alchemmist.xyz/homelab/wishlist` и вызов `alchemmist/deploy-to-socrat@v1`. Этот шаг записывает digest образа в репозиторий homelab. Argo CD подхватывает чарт и обновляет под.

Сам чарт, ingress, DNS и секреты живут в homelab, не здесь. Секрет пода даёт клиента Authentik, ключ сессии и ключ бакета. К порту RustFS 9000 под пускает сетевая политика `rustfs-isolation`, правило `wishlistMedia`. Учётная запись бакета отдельная: пользователь видит только бакет `wishlist`.

Публичное имя — `wishlist.alchemmist.xyz`, TLS выпускает cert-manager. DNS зоны ведётся на своих Knot, не записью у регистратора.
